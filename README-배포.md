# 등록폼 배포 가이드 — 교회 검색(네이버) + 등록 데이터 저장(구글시트)

## 0. 먼저 알아두실 것

교회 검색은 **네이버 지역검색 API**를 쓰는데, 이건 등록폼 HTML에서 직접 부를 수 없습니다.

1. 네이버 오픈API는 브라우저에서 오는 요청을 CORS로 막아둡니다 (브라우저가 차단).
2. 호출에 필요한 **Client Secret**을 HTML/JS에 넣으면 페이지 소스를 보는 누구나 가져갈 수 있습니다.

그래서 폼과 같은 도메인에 아주 작은 **프록시 함수**를 하나 같이 올려서, 폼 → 프록시 → 네이버 순으로 호출합니다. 키는 프록시(서버) 환경변수에만 둡니다.

> **로컬에서 HTML 파일을 그냥 더블클릭해서 열면** 프록시가 없으므로 교회 검색은 "검색을 불러오지 못했어요"로 표시되고 **직접 입력**으로 넘어갑니다. 이건 정상 동작이며, 아래처럼 배포하면 검색이 됩니다.

---

## 1. 네이버 검색 API 키 발급 — NAVER API HUB (네이버클라우드)

> **2026년 7월부터 발급처가 바뀌었습니다.** 예전에는 developers.naver.com "애플리케이션 등록"의 사용 API에서 "검색"을 고르면 됐지만, 지금은 그 목록에 검색이 아예 없습니다(로그인/전자문서/카페/캘린더/캡차만 남음). 검색 API 신규 신청은 **네이버클라우드에서 운영하는 NAVER API HUB**로 이관됐습니다.
>
> 헷갈리기 쉬운 것 두 가지:
> - 개발자센터의 **'카페' API는 무관** — 네이버 카페(커뮤니티) 글 검색용입니다.
> - 네이버클라우드의 **Maps도 무관** — 지도 표시/최적경로/주소↔좌표 변환용이라, "사랑의교회"처럼 **이름으로 장소를 찾는 기능이 없습니다.** 이용 신청하지 않아도 됩니다.

1. https://www.ncloud.com 가입/로그인 (네이버 계정으로 연동 가입 가능)
2. 콘솔에서 **NAVER API HUB** 를 찾아 **이용 신청**
3. **Application 등록** → 사용할 API에서 **검색** 선택 (지역검색이 검색 API에 포함되어 있습니다)
4. 발급되는 인증키 두 개를 복사해둡니다:
   - Client ID → 환경변수 `NAVER_APIHUB_KEY_ID` 에 넣을 값
   - Client Secret → 환경변수 `NAVER_APIHUB_KEY` 에 넣을 값

현재 무료로 제공되며(검색 API 합산 월 수십만 회 규모, 초당 50회 제한), 교회 규모에서는 넉넉합니다.

> 혹시 예전에 developers.naver.com에서 발급받아둔 키가 이미 있다면 그것도 그대로 쓸 수 있습니다 — `NAVER_CLIENT_ID` / `NAVER_CLIENT_SECRET` 환경변수로 넣으세요(2027-06-30까지 한시 지원). 프록시가 두 방식을 모두 인식하고, 둘 다 있으면 API HUB 쪽을 씁니다.

## 2-A. Netlify로 배포하는 경우

1. 이 `registration-form` 폴더를 통째로 Netlify에 올립니다
   (드래그 앤 드롭 배포 또는 GitHub 저장소 연결).
   - `netlify.toml`이 이미 들어있어서 함수 경로는 자동으로 잡힙니다.
2. Netlify 대시보드 → **Site configuration → Environment variables**에서 추가:
   - `NAVER_APIHUB_KEY_ID` = API HUB에서 발급받은 Client ID
   - `NAVER_APIHUB_KEY` = API HUB에서 발급받은 Client Secret
3. **Deploys → Trigger deploy** 로 다시 배포 (환경변수는 재배포해야 반영됩니다).
   - 등록 데이터 저장용 `SHEETS_WEBHOOK_URL` / `SHEETS_WEBHOOK_TOKEN` 두 개도 같이 넣으면 재배포를 한 번만 하면 됩니다 (4번 참고).

## 2-B. Vercel로 배포하는 경우

1. 이 `registration-form` 폴더를 Vercel 프로젝트로 올립니다.
   - `api/church-search.js`가 자동으로 `/api/church-search` 엔드포인트가 됩니다.
   - `netlify/` 폴더와 `netlify.toml`은 Vercel에서 무시되므로 지워도 되고 둬도 됩니다.
   - `api/register.js` 는 `/api/register` 엔드포인트가 됩니다.
2. 프로젝트 → **Settings → Environment Variables**에 위와 동일하게 추가 (`SHEETS_WEBHOOK_*` 포함).
3. 재배포.

## 3. 잘 되는지 확인

브라우저에서 아래 주소를 직접 열어봅니다 (배포 주소로 바꿔서):

```
https://내주소/api/church-search?q=사랑의교회
```

`{"items":[{"name":"사랑의교회", ...}]}` 형태로 나오면 성공입니다.

| 응답 | 뜻 | 조치 |
|---|---|---|
| `503 naver_credentials_missing` | 환경변수 미설정 | 위 2번 다시 확인 후 **재배포** |
| `502 naver_api_error` | 키가 틀렸거나 검색 API 미선택 | API HUB의 Application 설정에서 "검색" API가 선택돼 있는지, 키 값을 그대로 복사했는지 확인 |
| `400 query_length` | 검색어가 2자 미만 | 정상 동작 (폼에서도 2자부터 검색) |

## 4. 등록 데이터 저장 — 청년부 공용 구글시트 연결

등록 내용은 **청년부 공용 구글시트에 전용 탭을 만들어 한 줄씩 쌓이게** 되어 있습니다.
탭 이름은 `Code.gs` 맨 위의 `SHEET_NAME` 값(현재 `새가족 등록폼 data`)을 그대로 씁니다 — 바꾸고 싶으면 그 한 줄만 고치면 됩니다.
별도 DB(Supabase 등)를 만들 필요가 없고, 명단이 이미 있는 그 파일에서 바로 확인할 수 있습니다.

구조는 교회 검색과 똑같습니다: **폼 → 우리 프록시(`/api/register`) → 구글 Apps Script → 시트**.
Apps Script 웹앱 주소와 토큰은 **서버 환경변수에만** 두므로 폼 HTML에는 어떤 비밀값도 들어가지 않습니다.

### 4-1. 구글시트에 스크립트 붙여넣기

1. 청년부 공용 구글시트를 엽니다 (명단이 들어있는 그 파일).
2. 상단 메뉴 **[확장 프로그램] → [Apps Script]**
3. 편집기에 있던 기본 코드를 **전부 지우고**, `google-apps-script/Code.gs` 내용을 통째로 붙여넣습니다.
4. 왼쪽 **[프로젝트 설정 ⚙] → [스크립트 속성] → [스크립트 속성 추가]**
   - 속성 이름: `SHARED_TOKEN`
   - 값: 아무도 모르는 임의의 긴 문자열 (영문+숫자 32자 정도)
   - ※ 이 값을 안 넣으면 모든 요청이 거부됩니다. 반드시 넣으세요.
5. 상단 **[배포] → [새 배포]** → 유형 선택(⚙) → **[웹 앱]**
   - 설명: `새가족 등록 수집`
   - **실행 계정: 나(Me)**
   - **액세스 권한: 모든 사용자(Anyone)**
   - **[배포]** → 권한 승인 (본인 계정으로 시트를 수정하겠다는 승인입니다)
6. 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/AKfycb.../exec`)을 복사해둡니다.

> 등록 탭(`SHEET_NAME`)은 첫 등록이 들어오는 순간 머리글까지 갖춰서 **자동으로 만들어집니다.** 미리 만들어두셔도 되고, 안 만드셔도 됩니다.

### 4-2. 배포 호스트에 환경변수 추가

Netlify는 *Site configuration → Environment variables*, Vercel은 *Settings → Environment Variables*에 추가합니다.

- `SHEETS_WEBHOOK_URL` = 4-1의 6번에서 복사한 웹 앱 URL
- `SHEETS_WEBHOOK_TOKEN` = 4-1의 4번에서 정한 `SHARED_TOKEN` 과 **똑같은 값**

추가한 뒤 **재배포**해야 반영됩니다.

### 4-3. 확인

폼을 실제로 열어 한 건 제출해보면 시트에 행이 하나 생깁니다. 안 되면:

| 증상 | 뜻 | 조치 |
|---|---|---|
| "등록 시스템 준비 중입니다" | `SHEETS_WEBHOOK_*` 환경변수 미설정 (503) | 4-2 확인 후 **재배포** |
| "등록 중 문제가 발생했습니다" | 함수 로그에 `unauthorized` | 양쪽 토큰이 다름 — `SHARED_TOKEN` 과 `SHEETS_WEBHOOK_TOKEN` 값을 맞추세요 |
| 〃 | 함수 로그에 `sheet_unreachable` | 웹앱 배포가 "모든 사용자"가 아니거나 URL이 틀림 |
| 〃 | 함수 로그에 `sheet_write_failed` | 시트가 삭제·이름 변경되었는지 확인 |

Apps Script 코드를 고친 뒤에는 **[배포] → [배포 관리] → ✏️ → 버전 "새 버전" → [배포]** 를 눌러야 반영됩니다. 저장만으로는 반영되지 않습니다.

### 4-4. 시트에 만들어지는 열

| 열 | 내용 |
|---|---|
| 접수일시 | 서버 기준 제출 시각 (제출자가 조작할 수 없음) |
| 이름 / 성별 / 생년월일 / 연락처 | 폼 입력값 |
| 다니던 교회 / 교회명 / 교회 위치 | 교회 검색(네이버)에서 고른 결과. 목록에 없으면 직접 입력 |
| 교단 / 청년부 | **새가족이 직접 작성** — 교단은 자유 입력(선택), 청년부는 O/X 선택. 네이버가 주지 않는 정보라 폼에 입력칸을 따로 뒀습니다 |
| 세례 여부 / 방문경로 / 방문경로(기타) / 참석 희망 | 폼 입력값 |
| **응대 여부 / 메모** | **스태프 전용.** 폼에서는 절대 채워지지 않고 항상 비어서 들어옵니다 |
| 네이버 검색 원본 | 추후 교회 정보 보강용 원본 데이터 |

### 4-5. 개인정보 관련해 한 가지 확인하실 점

이 시트에는 새가족의 **이름·연락처·생년월일**이 쌓입니다.
청년부 공용 시트에 탭으로 두면 **그 스프레드시트에 접근 권한이 있는 사람 전원이 이 정보를 볼 수 있습니다.**

- 접근자가 새가족부/교구 스태프 정도로 한정되어 있다면 그대로 두셔도 됩니다.
- 공용 시트를 여러 부서·다수 인원이 함께 본다면, **별도 스프레드시트를 새로 만들어 소수에게만 공유**하고 거기에 스크립트를 붙이는 편이 낫습니다. 명단 쪽에서 필요한 값만 봐야 한다면 `IMPORTRANGE` 로 당겨쓸 수 있습니다.

둘 중 어느 쪽이든 코드는 그대로입니다 — 스크립트를 붙여넣는 스프레드시트만 달라집니다.

## 5. 지금 네이버 검색으로 채워지는 정보 / 안 채워지는 정보

| 항목 | 네이버 지역검색이 주는가 | 현재 처리 |
|---|---|---|
| 교회 이름 | O | 저장됨 |
| 위치(도로명/지번 주소) | O | 저장됨 |
| 전화번호·카테고리·좌표·네이버 링크 | O | `prior_church_naver` (jsonb)에 원본 그대로 저장 |
| **교단** | X | 폼에 입력칸 추가 — 새가족이 직접 작성 (몰라서 비워두면 빈칸) |
| **청년부 유무** | X | 폼에 **O/X 선택** 추가 — 새가족이 직접 선택 (시트에 O/X로 기록) |

교단과 청년부 유무는 네이버 지역검색이 제공하지 않는 정보라 **임의로 추측해 채우지 않고, 새가족이 폼에서 직접 적도록** 했습니다.
네이버 응답 원본(`네이버 검색 원본` 열)은 계속 저장되므로, 나중에 입력값을 검증·보강할 때 근거로 쓸 수 있습니다.
